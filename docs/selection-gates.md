# NotebookLM選別と更新確認を分担する新高値監視

2026-11-15改訂。選別根拠と判定理由を追跡する運用仕様。収益性を実証したモデルではない。

| プログラム／毎営業日16:00 JST | 最新の確定日足、出来高、ボックス、新高値、登録された必須条件を計算 |

## 一次選別の受入れ

`audit/shikiho_candidates_2026.json`の112銘柄は、利用者の指示によりNotebookLM選別済みリストとして採用する。`source_verified=false`を維持し、こちらで四季報原本を確認したとは記録しない。

`selection_acceptance`に受入日、方法、号の表示、各行のコード・入力社名・選定理由のハッシュを保存する。受入日前への適用、未承認の行追加、コード・選定理由の差替えは通過させない。原本未照合だけで全銘柄を保留しない。

受入前と受入後のリストを`audit/universe_history/`へ保存した。元の選定日が不明な場合はnullとし、受入日を過去の選定日に置き換えない。12月の再選別も旧版を残して新しい受入日・参照情報を登録する。

## 独立した6条件

1. **四季報選別**：上記の利用者承認付き受入れ、または原本照合の証拠で通過。
2. **銘柄同一性**：`audit/security_identity.json`の公式コード・社名照合。112件中110通過、3795は入力社名トヨクモ（公式4058）と不一致のため個別保留、2180は2026-09-16上場廃止のため除外。3695はコードを維持して表示社名をGMOプロダクトプラットフォームに訂正。受領リストの元の表記は保存。
3. **業績**：最新通期会社予想の営業利益が前期実績比20%以上増加し、EPSも増加することが通常条件。四半期累計、終了済み予想期間、異なる決算期間、連結・個別の混在を自動合格にしない。通常条件未達は根拠付きの例外審査へ。
4. **TOPIX**：公式完全リストの移行措置対象を除外。TOPIX採用そのものを必須にしない。新規組入れは公表後から実施日までS属性、実施後はA相当へ。S/Aは期待収益や勝率ではない。
5. **流動性**：5日平均の終値×出来高が4,000万円以上。実約定売買代金の近似であり、既存の分割・配当調整価格を用いる。
6. **価格**：取引所カレンダーで期待する最新確定日と日足の計算日が一致すること。

これらを通過しても、既存の技術条件を満たさなければ新規候補にはならない。前日まで250営業日の高値、当日を除く20日平均出来高比1.5倍、20～65本ボックス、初動3営業日、箱上限から3%以内という条件は変更していない。

最終状態はcandidate（候補）、watch（条件確認済み・技術待ち）、pending（確認待ち）、excluded（除外）で排他的。条件別の件数は重複し得る。技術上の状態と実際の候補採否は別属性に残す。

## 業績資料と追加開示確認

`audit/fundamental_evidence.json`は1社につき現在評価する1資料を保持する。公表日・対象期・比較可能性・出典・OP/EPSの4数値が必要。今回の更新前3資料は`audit/evidence_history/`に保存した。

`audit/disclosure_checks.json`は実際に追加開示を確認した記録。`evidence_key`で資料URL・公表日・対象期・数値に紐付ける。資料を読み直した日と、追加開示を点検した日は分離し、前者で後者を延長しない。最新性の合格は判定日当日の成功記録に限る。

`check_disclosure_updates.py`が登録済みの公式IR一覧または公式配信feedを取得する。承認済みの一覧と変化がなければ実取得日で確認記録を更新する。新項目・変更は再審査、取得失敗は確認待ち。新しい業績数値の自動採用・例外の自動承認は行わない。

自動監視の範囲は`audit/disclosure_monitors.json`で明示する。動的な一覧が取れない会社は、空のHTMLを「変更なし」として使わない。2026-11-15時点では公式一覧を確認できた5社を登録し、日本マイクロニクスとほぼ日は公式feedの取得失敗により手動確認を残す。両社の当日確認はTDnet配信一覧の実読を記録しており、公式feedの取得成功とは表記しない。

## TOPIX公式資料

2026-10-07公表・10-30実施の公式全件表から、移行措置683銘柄、新規追加35銘柄を登録。11-09公表・11-30予定の3銘柄も公表日・固有出典・実施日付きで分離登録した。112銘柄中は移行措置19、非該当93、新規組入れ該当0。

`check_topix_updates.py`は毎営業日に公式ページの関連ニュース欄を取得し、承認済みニュースとの追加・訂正を検知する。根拠リストのハッシュと当日の成功記録が一致して初めて通過する。新公表、取得失敗、一覧欠落、期限切れは確認待ち。リストの自動採用・有効期限の自動延長はしない。

登録の`valid_until=2026-11-29`は、次の公表済みイベント前に再確認するための運用期限。JPXが保証する有効期限ではない。ニュース欄に出ない公表や、同URLのPDFの無告知差替えまで完全検知する仕組みではない。

## 実行と表示

```bash
python check_disclosure_updates.py
python check_topix_updates.py
python scan.py
```

GitHub Actionsは上記を毎営業日16:00 JSTに実行する。関連コード・根拠ファイル変更時も実行する。全件株価取得失敗では既存JSONを上書きしない。部分失敗では同じ最新確定日の有効キャッシュだけを再利用し、その出所を表示する。

保存済み日足に対して受入れ・業績・TOPIXだけを再評価する場合は`python refresh_selection.py --as-of YYYY-MM-DD`。この操作は株価日・株価取得時刻を変更せず、選別の再評価時刻だけ更新する。

`strategy.version=3`と`selection_version=1`は互換性のため維持。Scriptable用の本体は`NewHighMonitor.js` v8。既存v7も更新済み候補・保留・除外データを読める。受入れ件数・銘柄照合待ちの表示には端末内JSの差替えが必要で、GitHubのJS更新だけでは端末内プログラムは変わらない。

## 資金管理と検証範囲

100万円の設定、100株単位、買値から10%の損切り水準、5日平均代金の1%という注文上限試算は維持。1取引の許容損失額は利用者未設定のためnull。株数上限を推奨株数として扱わず、注文は行わない。

今回のテストは出典・日付・ゲート・表示・取得失敗時の挙動の検証。取引サンプルからの勝率、期待値、PF、最大ドローダウン、シャープレシオ、統計的有意性を測定したものではない。現在の112銘柄を過去に遡って使うバックテストや、場中の公表時刻を持たない資料による当日売買バックテストには転用しない。
